# v0.2 账户层实施计划（已实现）

- **状态**：已实现并随 v0.2.0 发布（2026-11-16；W1-W4 全部完成，实施结果见第 9 节）。
- **依据**：[v0.2 账户层设计](v0.2-account-layer.md)、ADR-018/019/020、[v0.2 范围](v0.2-scope.md) 修订 1。
- **目标**：按“契约编辑 → 账户对账 → 账户级审核”的顺序实现账户层，不改变 Ledger 写入路径与人工批准不变量。
- **产品定位**：独立本地账户内核，不与 Beancount-Trans 或特定产品集成。

## 0. 已定决策（实现时不要重新讨论）

1. 对账**永不阻断**写入；`hard_deadline` 兼容读取但忽略，视为弃用。
2. 对账**不要求证据**；`note` 可选。
3. 对账支持可选 `--declared CUR=VALUE`；记录 `ledger_balances / declared_balances / differences`，差异只读，不自动调整、不自动提交。
4. 契约 schema 保持 `version: 1` 加法扩展；新增 `unmanaged_accounts`。
5. 契约编辑唯一入口：`contracts apply`，要求 `--expected-current` + `--confirm` 双哈希、原子写、审计。
6. 账户级审核只做分组视图；批准仍按 `draft_id + validation_id + ledger_revision + contract_revision`。
7. 发布前可推翻旧设计，但审计链/journal/已提交账本不可改写。

## 1. 工作包与顺序

### W1 契约编辑（先做）

**范围**

- `contracts.yaml` 增加可选 `unmanaged_accounts`；解析、校验、覆盖率。
- `Kernel` 提供契约只读视图与 apply 用例；CLI `contracts show/validate/diff/apply`。
- 契约变更审计 `ContractChanged`，旧/新内容入 blob；CAS 冲突 `CONTRACT_CONFLICT`。

**文件**

- `src/ledger_kernel/contracts.py`：`Contract.unmanaged_accounts`、`parse_contract` 顶层字段、覆盖率辅助。
- `src/ledger_kernel/kernel.py`：`contracts_view()`、`apply_contracts(...)`（持锁、校验、原子写、审计）。
- `src/ledger_kernel/cli.py`：`contracts` 子命令。
- `src/ledger_kernel/errors.py`：`CONTRACT_CONFLICT`。
- `src/ledger_kernel/store.py`：必要时暴露 blob/contract 路径（已有 `contracts_path`）。
- `tests/test_contracts.py`（新建）。

**接口草案**

```python
# kernel.py
def contracts_view(self) -> dict: ...          # 解析结果、revision、错误、覆盖率
def apply_contracts(self, text: str, *, expected_current: str, actor: str = "local-user", note: str | None = None) -> dict: ...
```

CLI：

```bash
ledger-kernel contracts show
ledger-kernel contracts validate --file contracts.new.yaml
ledger-kernel contracts diff --file contracts.new.yaml
ledger-kernel contracts apply --file contracts.new.yaml \
  --expected-current sha256:<current> --confirm sha256:<new> --note "..."
```

**测试**

- 合法 apply：文件替换、审计 `ContractChanged`、blob 可读、`ledger_revision` 不变。
- CAS 不符、缺失 `--expected-current`、非法 schema、`unmanaged_accounts` 与 `accounts` 重叠 → 拒绝且文件不变。
- 契约 apply 后 pending validation 失效，重验后可批准。
- 覆盖率与 `unmanaged_accounts` 计数。

**完成标准**：CLI/API 可用，测试全绿，README 双语更新。

### W2 账户对账（依赖 W1 的 cadence）

**范围**

- 审计事件 `AccountReconciled` / `AccountReconciliationReverted`；`state.json.reconciliations` 缓存与重建。
- `get_account` 增加 `assertion` 摘要与 `reconciliation` 视图。
- `CONTRACT_RECONCILIATION` 判据从“最后记账日”切到对账状态（`never`/`overdue` 才警告，仍不阻断）。
- CLI `accounts reconcile`、`accounts reconciliation list/revert`。
- 可选 `--declared CUR=VALUE`，差异只读。

**文件**

- `src/ledger_kernel/kernel.py`：`reconcile_account(...)`、`list_reconciliations(...)`、`revert_reconciliation(...)`、`_rebuild_reconciliations_locked()`。
- `src/ledger_kernel/contracts.py`：`evaluate_contract` 接收对账状态，`CONTRACT_RECONCILIATION` 改为按 `never`/`overdue` 警告。
- `src/ledger_kernel/store.py`：若需要状态缓存读写辅助。
- `src/ledger_kernel/cli.py`：`accounts` 子命令扩展。
- `src/ledger_kernel/errors.py`：`RECONCILIATION_INVALID`。
- `tests/test_reconciliation.py`（新建）。

**接口草案**

```python
def reconcile_account(self, account: str, *, as_of: date, declared: Mapping[str, Decimal] | None = None,
                      note: str | None = None, actor: str = "local-user") -> dict: ...
def list_reconciliations(self, account: str) -> list[dict]: ...
def revert_reconciliation(self, reconciliation_id: str, *, reason: str, actor: str = "local-user") -> dict: ...
```

CLI：

```bash
ledger-kernel accounts reconcile Assets:Bank:Checking --as-of 2026-11-30 \
  --declared CNY=1234.00 --note "与银行 App 一致" --confirm Assets:Bank:Checking
ledger-kernel accounts reconciliation list Assets:Bank:Checking
ledger-kernel accounts reconciliation revert rec_... --reason "抄错" --confirm rec_...
```

**测试**

- 记录成功；状态 `current/overdue/never/not_configured`；`next_due`。
- 未申报/零差异/非零差异/多币种；申报币种不在账本余额时 ledger=0。
- 无效账本、账户未开立、`as_of > today`、重复 as_of → `RECONCILIATION_INVALID`，不写。
- 撤销只能最新；撤销后状态回退；审计历史保留。
- 对账前后 `ledger_revision` 不变；缓存删除后从审计重建。

**完成标准**：对账可记录、可查、可撤销；不阻断任何提交。

## 7. 风险与回退

- **契约并发覆盖**：双哈希 CAS + 持锁；失败不改文件。
- **缓存损坏**：只信审计，缓存可删除重建。
- **对账误记**：撤销追加事件，不删除历史；对账永不阻断，避免卡住记账。
- **实现偏离设计**：先改 ADR/设计文档，再改代码；不在代码里留下未记录的行为。
