## 实施范围

- **P0-A**：Beancount Adapter、include 闭包枚举、账户树/余额、revision manifest、engine fingerprint。
- **P0-B**：Revision Observer、外部变化观测、来源标记、旧草稿失效、无效账本阻断。
- **P0-C**：不可变草稿、idempotency、临时工作区完整 Dry-run、ADR-012 增量断言、账户契约、diff 与 review digest。
- **P0-D**：人工批准、单 `write_target` 追加、写前快照、journal、二次校验、原子替换、崩溃恢复、哈希链审计。
- **P0-E（薄）**：MCP stdio 适配器，只暴露读取与提案工具，不暴露批准/提交。
- **附加**：`corrections propose <commit_id>` 生成冲销草稿，原交易不删除、不改写。

## 冻结的工程选择

| 事项 | 选择 |
| --- | --- |
| Beancount 版本 | `3.2.x`（本机 3.2.3），依赖 `>=3.2,<4`，升级需真实账本回归 |
| include 闭包 | `loader.load_file()` 的 `options_map["include"]`，并用根文件、entry source、文件系统三重校验 |
| 外部快照 | 闭包文件内容寻址 blob，默认上限 512 MiB，去重并保护当前 manifest/journal 基线 |
| 提交原语 | 同目录临时文件 + `fsync` + `os.replace` + 目录 `fsync`；最终整账本 revision 复查 |
| 历史错误基线 | 要求干净基线；有 Beancount 错误时阻断 validate/commit |
| 契约存储 | `.ledger-kernel/contracts.yaml`，`schema_version: 1`，严格字段、声明式 |
| MCP 传输 | stdio，一行一条 JSON-RPC；无批准/提交工具 |

## 关键安全不变量

- 结构化提案，不接受 Agent 原始 Beancount 文本；控制字符/换行注入直接 `UNSAFE_TEXT`。
- 完整加载后做增量断言：旧 entries 不消失、不修改；新增 entries 与提案逐项相等；options/插件与其他文件不变。
- 片段指纹覆盖实际追加字节；提交时重渲染并校验已存片段，篡改即 `FRAGMENT_MISMATCH`。
- 批准绑定 `draft_id + validation_id + ledger_revision + contract_revision`，非交互必须显式确认。
- 外部修改只观测、不覆盖；无效账本 `LedgerInvalid` 阻断受控提交；来源未知固定 `external_unknown`。
- 已知转移只在严格 hash 链匹配时成立；批量批准可在 `review_digest` 不变时沿用，不跳过重验。

## 已知限制

- `flock` 只协调内核写入，普通编辑器不遵守；最后 hash 检查与 `os.replace` 之间仍有理论竞态窗口。
- 外部变化来源目前固定 `external_unknown`，未接入 Git/OS audit 佐证。
- 余额 diff 为 posting 原始数量按币种求和，不做成本/价格换算；完整语义仍由 Beancount 校验。
- 单文件追加；无多文件事务、无自动审核分级、无完整审核 UI。
- 外部直接写入的交易没有稳定 `commit_id`，暂不能一键生成冲销草稿；需手工构造修正提案。
