# v0.2 范围建议（账户语义优先，2026-11-16 修订 1）

- **状态**：已冻结（2026-11-16，方向校准修订 1）。账户层为 v0.2 主线；写入管线为支撑。P1 账户层已随 v0.2.0 发布。
- **数据窗口**：2026-10-16 ~ 2026-11-16（4 周真实账单）。
- **数据来源**：库外 dogfood 过程记录；本文件只保留聚合指标，不含真实账本、商户、卡号或个人数据。
- **协议**：[dogfood.md](../dogfood.md)。
- **产品定位**：独立的本地账户内核，不计划与 Beancount-Trans 或特定产品集成；导入/解析由外部提供，内核只接收结构化交易。
- **设计文档**：[v0.2 账户层设计](v0.2-account-layer.md)（已实现，v0.2.0）与[实施计划](v0.2-account-layer-plan.md)。

> **方向校准（2026-11-16，修订 1）**：初版把 dogfood 的五项写入指标当成产品方向，排序偏向审核 UI、导入去重与批量性能，弱化了账户语义。顶层设计摘要明确“账户是产品核心”，账户分定义/状态/契约三层，并要求“只做账户就要把第三层做深；否则会退化成账户列表”。本次样本使用空契约、单一 `write_target`，未覆盖账户层，因此 0 dry-run 阻断、0 手工改文件不能作为降级契约/对账的证据。以下按“账户层优先、写入管线支撑”重排；五项指标保留为写入闭环健康指标。

## 样本

| 项 | 值 |
| --- | --- |
| 窗口 | 4 周（2026-10-16 ~ 2026-11-16） |
| 账单行数 | 90 |
| 经内核完整闭环新增 | 36 笔（submit → validate → approve → commit） |
| 已在账本、用于对账/去重判断 | 51 行 |
| 交易关闭 / 退款 | 14 行 / 13 行（净额为零或部分退款覆盖） |
| 写入位置 | 账本副本的单一 `write_target`；原账本未修改 |
| 手工改文件 | 0 次 |

覆盖情况：以日常支出为主，含 3 笔小额投资收益、2 笔部分退款、1 笔分期购买；4 周窗口内没有新增工资收入与账户间转账。**收入、转账与完整冲销场景的证据有限**，相关结论只作弱证据。

## 判据结论（按协议顺序，命中即排序）

1. **未命中**：没有 recovery、审计链异常或重复提交，不进入“暂停新功能”分支。
2. **命中**：中位 69.5 秒 > 60 秒。审核前端仍需优先，但应从“逐笔 diff”转为“按账户组织”的批量审核（见候选表）。
3. **不成立（样本限制）**：0 阻断来自空契约与单一 `write_target`，不能据此降级契约编辑；契约层提升为 P1 主线。
4. **未命中**：观测事件 0，Git/OS audit 归因暂缓。
5. **不构成否决**：0 手工改文件只覆盖当前样本；自动审核分级仍是原设计保留的长期方向，前置是契约层成熟，不在 v0.2 实现。

## P0 缺陷（已修复）

dogfood 暴露的两个批准可靠性缺陷已在 v0.2 范围冻结前修复：

- **Engine fingerprint 绑定 Python 运行时**：审核端与起草端解释器不同即触发 `EngineChanged`，全部 validation 失效，批准静默失败。已按 ADR-014 移除 Python 运行时，指纹只含 Beancount 与 ledger-kernel 版本。
- **空 `write_target` 首笔提交使批量批准失效**：首笔提交后追加分隔符从无到有，其余草稿 `review_digest` 变化，`ApprovalCarriedForward` 不生效。已按 ADR-015 改为哈希交易正文，空账本批量批准一次完成。

两项都有回归测试；修复前的 69.5 秒中位数值保留在本节上方作为历史基线，修复后的同规模复测待下一轮 dogfood。

## 明确否决 / 降级

- **Git/OS audit 归因**：0 观测事件，暂缓/降级。
- **自动审核分级**：不在 v0.2；原设计保留为契约成熟后的长期方向，不以 0 手工改文件否决。
- **契约编辑与账户提示**：提升为 P1 主线（样本未覆盖，不能按 0 阻断降级）。
- **回填历史交易**：只有 1 次尝试且被 pad/balance 断言正确阻断，保持 fail-closed，不进入 v0.2。
