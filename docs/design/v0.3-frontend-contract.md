# v0.3 前端只读 JSON 契约

- **状态**：已冻结（2026-11-16，v0.3 审核闭环）。
- **适用**：同仓库 `frontends/review-tui/` 与任何外部前端；内核不感知前端。
- **依据**：[v0.3 范围与明确非目标](v0.3-scope.md) 第 4 节「前端形态与宿主」。

## 1. 契约原则

1. 唯一交互面是 CLI 的 `--json` 输出与现有写入命令；前端**不 import** `src/ledger_kernel`。
2. 只读命令可在小版本内**加法扩展**字段；前端必须忽略未知字段。删除字段、改变类型或语义属于 breaking，需要修订本文并给兼容窗口。
3. ID（`draft_id`、`validation_id`、`reconciliation_id`、`commit_id`）是不透明字符串，前端只透传，不解析。
4. 金额一律为十进制字符串（如 `"25.00"`），前端不得转成 JSON float 再回写；时间戳为 ISO 字符串；布尔为 JSON true/false。
5. 没有 `--auto`、`--yes`、账户级批量批准路径；批准必须由人输入确认串。
6. 退出码：0 成功、2 稳定错误、其他为环境/崩溃。错误 JSON 固定为：

```json
{"ok": false, "error": {"code": "STABLE_CODE", "message": "...", "details": {}}}
```

## 2. 只读命令

以下命令均由 `ledger-kernel --ledger DIR --json ...` 调用。

### 2.1 `review`（待审队列）

```json
{"mode": "queue", "drafts": [{
  "draft_id": "str", "state": "str", "stale": true,
  "validation_id": "str|null", "agent": "str|null",
  "transactions": 1, "accounts": ["str"],
  "narration": "str", "created_at": "str",
  "date": "str", "payee": "str|null", "amount": "str", "currency": "str",
  "validation_status": "str|null", "checks": [{"code": "str", "severity": "str", "message": "str", "account": "str|null"}]
}]}
```

- 默认状态集合：`Submitted`、`NeedsHumanApproval`、`Blocked`、`Approved`；`--state` 只保留一种。
- `checks` 只用于展示；前端不得复制成自己的阻断逻辑。

### 2.2 `review DRAFT_ID`（草稿详情）

```json
{"mode": "detail", "drafts": [{
  "draft_id": "str", "state": "str", "validation_status": "str|null",
  "checks": [ ... ], "fragment": "str",
  "diff": {
    "changed_files": ["str"], "deltas": [{"account": "str", "currency": "str", "before": "str", "after": "str", "delta": "str"}],
    "balances_before": [{"account": "str", "currency": "str", "amount": "str"}],
    "balances_after": [{"account": "str", "currency": "str", "amount": "str"}],
    "postings": [{"date": "str", "payee": "str|null", "narration": "str", "account": "str", "units": "str", "currency": "str"}],
    "file_diff": "str", "fragment_preview": "str", "diff_unavailable": true
  },
  "draft": { "draft_id": "str", "transactions": [ ... ], "evidence": [ ... ], "confidence": 0.9, "...": "实现字段" }
}]}
```

- `draft` 中的 `confidence` 是唯一允许的浮点数；其余金额字段仍为字符串。
- `draft._kernel` 等内部字段可能变化，前端不得依赖。

### 2.3 `review --by-account [--account NAME] [--state S]`（按账户分组）

```json
{"mode": "by_account", "account": "str|null", "note": "str|null", "groups": [{
  "account": "str", "lifecycle": "str",
  "balances": {"CNY": "str"},
  "contract": null,
  "reconciliation": {
    "status": "not_configured|never|current|overdue",
    "last": null,
    "difference_status": "none|zero|nonzero",
    "next_due": "str|null"
  },
  "pending_drafts": [{"draft_id": "str", "date": "str", "amount": "str", "currency": "str", "narration": "str", "state": "str", "validation_status": "str|null"}],
  "warnings": [{"draft_id": "str", "code": "str", "severity": "str", "account": "str|null", "message": "str"}],
  "draft_count": 1
}]}
```

- 未知账户：`groups: []`，`note: "unknown account: <name>"`，退出码仍为 0；前端显示 note 即可。
- 一条草稿会出现在其 `account_refs` 的每个账户组下；前端自行去重展示。
- `warnings` 仅来自 latest validation 的 `CONTRACT_*` warning，不复制成阻断。

### 2.4 `accounts list [--as-of D] [--coverage]`

- 不带 `--coverage`：返回账户行数组，每行：

```json
{"account": "str", "lifecycle": "str", "open_date": "str|null", "close_date": "str|null",
 "currencies": ["str"], "booking": "str|null", "balances": {"CNY": "str"},
 "aliases": ["str"], "contract": null, "pending_drafts": 0,
 "assertion_status": "unset|asserted", "last_assertion": null,
 "reconciliation": {"status": "str", "last": null, "difference_status": "str", "next_due": "str|null"}}
```

- 带 `--coverage`：返回 `{"accounts": [...], "coverage": {...}, "unmanaged_accounts": ["str"]}`；`coverage` 键见 `contracts show`。
- `--as-of` 只影响余额与生命周期展示，不影响对账状态（按 today 推导）。

### 2.5 `accounts show ACCOUNT [--as-of D]`

在 2.4 行字段基础上增加：

```json
{"definition": {"open_date": "str|null", "close_date": "str|null", "currencies": ["str"], "booking": "str|null", "source_file": "str", "source_line": 1},
 "last_posting_date": "str|null", "note": "str"}
```

- 未知账户返回退出码 2、`ACCOUNT_NOT_FOUND`。

### 2.6 `contracts show`

```json
{"contract_path": "str", "contract_revision": "str", "schema_version": 1,
 "valid": true, "error": null,
 "account_count": 0, "accounts": {"Assets:...": {"aliases": [], "allowed_agents": [], "allowed_currencies": [], "allowed_tags": [], "required_tags": [], "reconciliation": {"cadence": "str|null", "hard_deadline": false}, "balance_policy": {"mode": "str", "min": "str|null", "max": "str|null"}}},
 "unmanaged_accounts": ["str"],
 "coverage": {"active_account_count": 0, "managed_accounts": ["str"], "unmanaged_accounts": ["str"], "uncovered_accounts": ["str"], "unopened_contract_accounts": ["str"], "inactive_contract_accounts": ["str"], "ratio": 0.0},
 "warnings": [{"code": "str", "severity": "str", "account": "str", "message": "str"}]}
```

- 契约无效时 `valid=false`、`error={code,message,details}`；读取命令本身仍退出 0。
- `coverage.ratio` 是唯一允许的浮点数。

## 3. 写入契约（仍走现有 CLI）

- 校验：`drafts validate DRAFT_ID --json`（返回 validation 记录，字段以现有实现为准）。
- 批准：`drafts approve DRAFT_ID [DRAFT_ID ...] --confirm "<id1,id2,...>" --json`。
  - `--confirm` 必须**精确等于**按参数顺序逗号拼接的 draft_id 列表；不匹配或缺失即 `INVALID_STATE`，非交互模式绝不自动确认。
  - 前端必须在 UI 中要求人手动输入该确认串；不得提供跳过、自动或账户级一键批准。
  - 批准绑定 `draft_id + validation_id + ledger_revision + contract_revision`；过期/失效由内核返回 `STALE_REVISION`/`INVALID_STATE`，前端提示重验。
- 前端不得直接写 `contracts.yaml` 或 Ledger；契约编辑/对账继续走 CLI（v0.3 不为其做 UI）。

## 4. 前端需要识别的错误码

`APPROVAL_REQUIRED`、`STALE_REVISION`、`INVALID_STATE`、`DRAFT_NOT_FOUND`、`VALIDATION_NOT_FOUND`、`CONTRACT_INVALID`、`CONTRACT_CONFLICT`、`RECONCILIATION_INVALID`、`ACCOUNT_NOT_FOUND`、`KERNEL_BUSY`、`CONFIG_INVALID`、`AUDIT_INTEGRITY`。未知 code 原样展示 `code + message`，不要猜测含义。

## 5. 契约测试与变更

- 内核仓库：[tests/test_cli_json_contract.py](../../tests/test_cli_json_contract.py) 固定以上字段、类型、错误壳与“无自动批准”的 CLI 行为。
- 前端测试用固定 JSON fixtures 或对 CLI 的集成测试，并固定 `ledger-kernel` 版本区间。
- 修改契约：先改本文与测试，再改实现；加法字段不强制前端升级，breaking 需版本说明与兼容窗口。

## 6. 明确不做

- 不提供 Python 对象或内部模块导入契约；不提供网络 API、事件流或 WebSocket；暂不做分页协议（输出量超限时再单独设计）。
- 前端不获得新的写入路径；不提供账户级批量批准、自动批准或“跳过确认”。
