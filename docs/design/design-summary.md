## 顶层设计摘要

### 一句话定位

**本地账本账户内核 + 外置 Agent + 可替换前端。**  
账本文件是唯一真相源；账户是产品核心；AI 外置为 Agent；同步、报表、导入、备份由外部生态提供。

### 核心命题

- 数据本地：账本是用户可访问、可导出、可带走的纯文本 Beancount 文件。
- 能力本地：账户读写、校验、对账、草稿、审计与撤销在本机完成。
- 交互可替换：CLI、编辑器、DSH、PWA 都只是前端。
- AI 外置：Agent 只提案，主账本由内核写入；但**不假设 Agent 永远不直写**，见「写入权」。

### 写入权

| 主体    | 权限                                         |
| ----- | ------------------------------------------ |
| 内核    | 所有**自动化写入**的唯一受控入口                         |
| 用户    | 保留直接编辑账本的**最高权限**，可用任何编辑器、Git、`bean-check` |
| Agent | 默认经收件箱或本地 API/MCP 提案；用户也可直接让它改本地文件         |

- 内核不垄断真相。用户手改是外部事实，内核重扫后接受，不覆盖、不静默修复。
- 用户直连 Agent 改账本无法禁止，也不需要禁止。内核的职责从「控制」转为「可观测」：重扫账本发现内容变化（hash 只证明"变了"，不证明"谁改的"）；有基线时给出 diff；依据 Agent 报告、Git、系统审计等可用证据标记来源，无证据时记为 external_unknown；变化以独立的观测事件记录并提示，不冒充内核提交。
- 允许绕过校验，但绕过会被看见：非法或不平衡的账本在下次加载时报告，不隐藏。

### 角色

1. **本地账户内核**：账户定义/状态/契约的唯一实现；接收草稿，调用 `beancount` 做完整校验并出 dry-run diff；确认或自动提交后落盘，记录审计，提供撤销。
2. **外置 Agent**：理解证据、匹配/建议账户、生成草稿，经收件箱或本地 API/MCP 提交；可替换、可外置。
3. **前端**：展示账户树、余额、待确认、diff；承担确认、驳回、对账、撤销。
4. **外部生态**：同步、报表、导入、备份、通知。

### 校验：不自己实现

- 交易能否合法写入，涉及完整 Beancount 语法与记账约束（平衡、`open`/`close`、货币、指令顺序、`pad`/`balance`）。
- 直接调用 Python `beancount` 做校验，内核不重写解析器，也不维护"校验子集"。
- "只实现账户子集"只约束**产品语义范围**（账户、交易、对账、余额断言），不约束校验完整性。

### 账户语义三层

- **定义**：开立、层级、别名、货币、关闭。
- **状态**：余额、待确认草稿、已对账/未对账、余额断言。
- **契约**：允许的交易类型、对账周期、预期余额范围、Agent 写入范围、标签约束。

只做账户就要把第三层做深；否则会退化成账户列表。

### 审核分级

MVP 阶段不做。

| 风险  | 判据                 | 处置         |
| --- | ------------------ | ---------- |
| 低   | 已知商户、小额、周期性、在账户契约内 | 自动提交，给撤销窗口 |
| 高   | 新账户、大额、异常模式、证据缺失   | 强制确认，置顶    |

- 阈值与规则可调、可审计；拿不准按高风险处理。
- 撤销窗口内前台可见、一键反向，过期即视为接受。

### 撤销与审计

- 每次内核写入记录：谁、何时、来源（Agent/用户）、改了什么、前后 hash、补丁。
- 撤销以**内核写入**为单位：默认生成冲销分录（同样经草稿、校验、确认）；仅当该块仍位于 write_target 末尾且文件 hash 等于提交时的 after_hash，才允许物理移除，作为"刚提交就发现点错"的快捷路径。不承诺"回到任意时间点"。
- 用户手改与外部同步不由内核回滚；内核以独立的观测事件记录所发现的变化，仅提供经冲突检查的恢复/反向补丁建议，由用户决定是否应用。
- 同步冲突可能留下中间态：以整文件 hash 发现漂移，触发重扫与提示。
- Git 历史是可选的版本历史补充，不替代内核审计（未提交的工作区变化不进入 Git 历史，Git author 也不是身份证明）；索引与缓存可从纯文本重建。

### 格式与兼容性

- 纯文本 Beancount；用户可用任何编辑器、Git、桌面 `bean-check`。
- 不引入私有二进制作为真相源；SQLite 等仅作可重建索引。
- 移动端：iOS Files 目录 + 安全作用域书签；Android SAF。

### 底线

1. 账本用户可访问、可导出、可带走（含 .ledger-kernel/ 中的契约、草稿、审计，均为可读文件）。
2. 写入前用 `beancount` 做完整语法与记账校验。
3. 备份/导出是底线能力。

### 明确不做

- 不做预算、通知、消费分析仪表盘。
- 不做内置同步黑盒、云账户体系、银行导入。
- 不内嵌 AI 推理，不绑定模型。
- 不做完整移动 App 作为起点。
- 不试图用权限禁止 Agent 直写账本。

### 成功判据

> Agent 提交草稿 → 内核用 beancount 校验并出 diff → 用户确认（v0.1 全部人工确认，分级自动提交留待后续）→ 内核提交并留下审计、可撤销；绕过内核的变化在下次扫描时被发现，来源按可用证据标记，无法归因即标记未知。

闭环在真实账户上比手工记账更快、更少出错、更可审计；成立则前端只是壳。

### 首屏

> **本项目是本地账本账户内核，不是记账 App。**  
> 账本是唯一真相源，账户是核心语义，Agent 是外置行动者，前端可替换。内核是所有自动化写入的受控入口；用户保留最高编辑权。绕过内核的文件变化会在下次扫描时被发现；内核尽可能保存差异，并依据可用证据标记来源，无法可靠归因时明确标记未知。内核写入可按提交记录撤销；外部修改只提供经冲突检查的恢复建议，由用户决定是否应用。
