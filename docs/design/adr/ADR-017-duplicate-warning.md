# ADR-017：重复流水只做校验期告警，不阻断提交

状态：[建议冻结]

**背景**
dogfood 中导入 4 周账单时，18 行历史流水有 17 行已存在；完整 CSV 的 90 行里也有大量已在账本中的记录。v0.1 没有去重，重复导入会静默多记，审计链看不出差别。另一方面，同一天同金额同账户的合法重复（两笔 0.00 医保、两次相同充值）确实存在，硬阻断会误伤。

**决策**
1. dry-run 增加 `DUPLICATE_SUSPECTED` 告警（`severity=warning`，不阻断）：
   - 与账本已有交易比较 `date + 账户 + 绝对金额` 签名；
   - 同一份草稿内两笔交易签名相同也告警。
2. 只告警不阻断；是否记入账本由人工审核决定。
3. 该告警是**建议性**的，不进入 `review_digest`（ADR-015）：合法重复不应在批量提交中途使已批准的草稿失效。
4. 关闭订单、退款配对、改价重下仍由 Agent/导入端判断；v0.1 不新增 CSV 导入器，也不自动冲销外部交易。

**后果**
- 重复导入从“静默接受”变为“可见告警”，但不改变人工批准的最终决定权。
- 同一天同金额同账户的合法重复会看到告警，需要审核者自行判断。
- 无新增阻断路径；提交仍只受 Beancount 校验、增量断言与账户契约约束。

**验收**
- 重复提交一笔已入账交易时 validate 返回 `pass_with_warnings` 且包含 `DUPLICATE_SUSPECTED`（`tests/test_dryrun.py::test_duplicate_of_existing_transaction_is_a_warning`）。
- 两笔相同草稿在同一批次批准后仍可依次提交（告警不进入 digest）。
- 关闭/退款场景不在内核自动配对，文档明确由 Agent 判断。
