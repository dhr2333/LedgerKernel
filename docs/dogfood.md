# 真实账本 Dogfood 记录（v0.2.x 账户层轮次）

本文件规定 v0.2.x 的真实账本使用协议。目的不是再验证一遍单元测试，而是回答两个问题：

1. 在真实账户上，内核闭环是否比手工记账更快、更少错、更可审计？
2. v0.2 账户层（契约编辑、账户对账、账户级审核）是否真的减少了往返，而不是退化成账户列表？

结论必须来自实际使用数据，而不是功能愿望清单。没有数据，不为 v0.3 排优先级。

## 安全边界

- 只用一份**账本副本**；原账本目录保持只读，不在 dogfood 中修改。
- 开始前做一次完整备份，并记录副本的 `ledger_revision`（`ledger-kernel status`）。
- 发现缺陷时记录 issue 并按正常流程修复；不要在 dogfood 过程中顺手改内核行为。
- 不把真实账本、`.ledger-kernel/`、证据文件或个人信息提交进仓库。

## 样本与时长

- 2–4 周，至少 20 笔真实交易。
- 覆盖四类：日常支出、收入、账户间转账、对错误交易的冲销/修正。
- 每笔都走完整闭环：提交草稿 → `validate` → `approve` → `commit`；不跳过 dry-run，不使用批量捷径。
- 账户层要求（本轮新增）：
  - 至少 2 个资产/负债账户配置契约；至少 1 个月度 cadence。
  - 轮次内完成至少一次对账（含可选申报余额），并对差异作出解释（不自动调整）。
  - 至少使用一次 `review --by-account` 完成实际审核。
  - 账户层操作只写 `.ledger-kernel/`，不写 Ledger；不得为让状态好看而伪造对账。

## 每周汇总

在账本副本目录运行（全局参数放在子命令前）：

```bash
ledger-kernel --json status
ledger-kernel drafts list
ledger-kernel audit --limit 100
ledger-kernel observations list
ledger-kernel recovery status
ledger-kernel contracts show
ledger-kernel --json accounts list --coverage
ledger-kernel accounts reconciliation list Assets:Bank:Checking
ledger-kernel review --by-account
```

记录：草稿状态分布、审计事件数、观测事件数、recovery 状态、平均确认耗时，以及上表的账户层指标。

## 从数据到决策（按顺序，命中即排序）

1. **出现 recovery、审计链异常或提交重复**：暂停新功能，先修复并补 ADR 与回归测试。
2. **提交→批准耗时中位数 > 60 秒，或同类字段反复填写**：优先做最小审核前端与草稿模板，而不是归因。
3. **dry-run 阻断 ≥ 30%，且集中在账户/契约**：优先做契约编辑与账户提示。
4. **观测事件 ≥ 3 次且原因不明**：才考虑接入 Git/OS audit 归因；否则降级。
5. **手工改文件 ≥ 20%**：先补前置校验、证据采集或草稿生成，不引入自动审核分级。
6. **契约覆盖率 < 80%，或整轮不增长**：优先契约编辑/覆盖率工作流（含 `unmanaged` 显式声明），不加自动修复。
7. **有 cadence 的账户对账及时率 < 80%，或 stale > 0**：优先对账总览与提示（只读聚合），仍不阻断写入。
8. **`review --by-account` 的实际审核耗时没有低于逐笔审核**：再评估账户级交互；任何账户级批量批准须新 ADR。
9. **申报差异无法解释或反复录错**：改善申报输入与差异展示，不自动生成调整分录。

## 结论落在哪里

- 汇总写入仓库 `docs/design/` 下的轮次报告（本轮为 `v0.2-dogfood-round2.md`）；库外笔记只放过程记录，不作为规范。
- 结论至少包含：样本量与时长、五项写入指标与账户层指标的实测值、发现的摩擦点与修复项、据此对 v0.3 候选的排序建议。
